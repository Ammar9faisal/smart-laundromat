# Smart Laundromat REST API

Base URL (local): `http://127.0.0.1:8000`

Interactive documentation generated by FastAPI: `http://127.0.0.1:8000/docs`

## Conventions

- Requests and responses use JSON.
- Times are ISO 8601 strings **with a time zone offset** (for example `2026-11-25T14:00:00-05:00` or `...Z`). Times without an offset are rejected with 422. The database stores everything in UTC.
- Protected endpoints need the Supabase access token of the signed-in user:
  `Authorization: Bearer <access_token>`
- Errors have the shape `{"detail": "..."}`. Validation errors (422) from FastAPI have `detail` as a list of `{loc, msg, type}` objects.

### Status codes

| Code | Meaning |
|---|---|
| 200 | OK |
| 201 | Created |
| 204 | Done, no body |
| 401 | Missing, invalid or expired access token |
| 402 | Simulated card was declined (payment recorded as FAILED) |
| 403 | Signed in, but not allowed (for example a customer calling an admin endpoint) |
| 404 | Not found, or belongs to another customer |
| 409 | Conflict: overlapping reservation, or the reservation is in a state that does not allow the action |
| 422 | Invalid input, or the machine is out of service / inactive |
| 500 | Unexpected server error |
| 503 | Database or Supabase Auth unreachable (the token may still be valid, so clients should not log the user out), or payments not configured (`SUPABASE_SECRET_KEY` missing) |

### Access levels

| Level | Meaning |
|---|---|
| Public | No token needed |
| User | Any signed-in user. Customers only ever see their own reservations and payments; administrators see everyone's |
| Admin | Signed-in user whose profile role is `admin` (checked on the server) |

## Authentication

Sign-up, sign-in, sign-out and sessions are handled by Supabase Auth in the frontend. The API verifies the resulting access token.

### `GET /api/auth/me` — User

The caller's profile.

`200`
```json
{"id": "uuid", "full_name": "Sam", "role": "customer", "created_at": "...", "email": "sam@example.com"}
```
`401` no or invalid token

### `GET /api/auth/admin-test` — Admin

`200` → `{"message": "Admin access granted", "user_id": "uuid"}` · `401` · `403`

## Machines

Machine object:
```json
{"id": 1, "type": "WASHER", "capacity": 8, "price": 4.5, "status": "AVAILABLE", "active": true}
```
- `type`: `WASHER` | `DRYER`
- `status`: `AVAILABLE` | `RESERVED` | `IN_USE` | `OUT_OF_SERVICE`
- `capacity` in kg, `price` per reservation in CAD

### `GET /api/machines/` — Public

Active machines.

| Query parameter | Type | Description |
|---|---|---|
| `type` | `WASHER` \| `DRYER` | optional filter |
| `status` | machine status | optional filter |
| `min_capacity` | integer > 0 | optional, capacity ≥ value |

`200` → list of machines · `422` invalid filter

### `GET /api/machines/available` — Public

Active, in-service machines with no reservation overlapping the window.

| Query parameter | Type | Description |
|---|---|---|
| `start_time` | datetime | required |
| `end_time` | datetime | required, after `start_time` |
| `type` | `WASHER` \| `DRYER` | optional |

`200` → list of machines · `422` invalid or reversed window

### `GET /api/machines/{machine_id}` — Public

`200` → machine · `404` not found or inactive

### `GET /api/machines/{machine_id}/availability` — Public

Busy time ranges (without who booked them).

| Query parameter | Type | Description |
|---|---|---|
| `from` | datetime | required |
| `to` | datetime | required, at most 31 days after `from` |

`200`
```json
{
  "machine_id": 1,
  "from_time": "2026-11-25T05:00:00Z",
  "to_time": "2026-11-26T05:00:00Z",
  "busy": [{"start_time": "2026-11-25T14:00:00Z", "end_time": "2026-11-25T15:00:00Z"}]
}
```
`404` machine not found · `422` invalid window

### `POST /api/machines/` — Admin

Request:
```json
{"type": "WASHER", "capacity": 12, "price": "6.25", "status": "AVAILABLE", "active": true}
```
`capacity` 1–100, `price` 0–1000 with at most 2 decimals, `status` and `active` optional. Unknown fields are rejected.

`201` → machine · `401` · `403` · `422`

### `PATCH /api/machines/{machine_id}` — Admin

Any of `type`, `capacity`, `price`, `active` (at least one).

`200` → machine · `401` · `403` · `404` · `422`

### `PATCH /api/machines/{machine_id}/status` — Admin

Request: `{"status": "OUT_OF_SERVICE"}`

`200` → machine · `401` · `403` · `404` · `422`

### `DELETE /api/machines/{machine_id}` — Admin

Deactivates the machine (`active = false`). Machines are never deleted so past reservations keep their machine.

`204` · `401` · `403` · `404`

## Reservations

Reservation object:
```json
{
  "id": 7,
  "user_id": "uuid",
  "machine_id": 1,
  "start_time": "2026-11-25T14:00:00+00:00",
  "end_time": "2026-11-25T15:00:00+00:00",
  "status": "PENDING_PAYMENT",
  "price": 4.5,
  "expires_at": "2026-11-23T18:15:00+00:00",
  "created_at": "...",
  "updated_at": "...",
  "machine": {"id": 1, "type": "WASHER", "capacity": 8, "price": 4.5, "status": "AVAILABLE"}
}
```
`status`: `PENDING_PAYMENT` → `CONFIRMED` (paid) → `IN_PROGRESS` → `COMPLETED`, or `CANCELLED` / `EXPIRED`. An unpaid reservation holds its slot until `expires_at` (15 minutes by default).

### `POST /api/reservations` — User

Request:
```json
{"machine_id": 1, "start_time": "2026-11-25T14:00:00Z", "end_time": "2026-11-25T15:00:00Z"}
```
Rules: start in the future and at most 30 days ahead; 15 minutes to 3 hours long; machine active and not out of service; no overlap with another active reservation for the same machine (enforced by the database, also for simultaneous requests). The customer is taken from the access token, never from the body.

`201` → reservation (`PENDING_PAYMENT`) · `401` · `404` machine not found · `409` overlapping reservation · `422` invalid times or machine out of service

### `GET /api/reservations` — User

| Query parameter | Type | Description |
|---|---|---|
| `mine` | boolean | only the caller's reservations (useful for admins) |
| `status` | reservation status | optional filter |
| `machine_id` | integer | optional filter |
| `limit` | 1–500 | default 100 |

Newest start time first. `200` → list of reservations · `401` · `422`

### `GET /api/reservations/{reservation_id}` — User

`200` → reservation · `401` · `404` not found or another customer's

### `DELETE /api/reservations/{reservation_id}` — User (owner) or Admin

Cancels a future `PENDING_PAYMENT` or `CONFIRMED` reservation. A successful payment is refunded when the cancellation is more than 15 minutes before the start.

`200` → reservation (`CANCELLED`) · `401` · `404` · `409` already started, cancelled, completed or expired

## Payments

Payments are simulated. Only test payment methods are accepted, so real card details can never be submitted.

| `payment_method` | Result |
|---|---|
| `pm_card_visa` | succeeds |
| `pm_card_mastercard` | succeeds |
| `pm_card_chargeDeclined` | declined: "Your card was declined." |
| `pm_card_chargeDeclinedInsufficientFunds` | declined: "Your card has insufficient funds." |

Payment object:
```json
{
  "id": 11, "reservation_id": 7, "user_id": "uuid",
  "amount": 4.5, "currency": "CAD", "status": "SUCCEEDED",
  "provider": "SIMULATED", "provider_ref": "sim_3f2a...", "failure_reason": null,
  "created_at": "...", "updated_at": "..."
}
```
`status`: `SUCCEEDED`, `FAILED`, `REFUNDED` (`PENDING` is reserved for a future real gateway).

### `POST /api/payments` — User (owner of the reservation)

Request:
```json
{"reservation_id": 7, "payment_method": "pm_card_visa", "idempotency_key": "3b6f0c2e-..."}
```
`idempotency_key` is optional (8–100 characters: letters, digits, `-`, `_`). Repeating a request with the same key returns the original payment instead of charging again.

The amount comes from the reservation, never from the request.

| Status | Body | When |
|---|---|---|
| `201` | payment (`SUCCEEDED`) | paid; reservation is now `CONFIRMED` |
| `200` | payment | repeated request with the same idempotency key |
| `402` | `{"detail": "Your card was declined.", "payment": {...}}` | declined; payment recorded as `FAILED`, reservation stays `PENDING_PAYMENT` so the customer can retry |
| `401` | | no or invalid token |
| `404` | | reservation not found or another customer's |
| `409` | | already paid, cancelled or expired, or idempotency key used for another reservation |
| `422` | | unknown payment method, card details or other unexpected fields |
| `503` | | `SUPABASE_SECRET_KEY` not configured |

### `GET /api/payments` — User

| Query parameter | Type | Description |
|---|---|---|
| `mine` | boolean | only the caller's payments |
| `reservation_id` | integer | optional filter |
| `status` | payment status | optional filter |
| `limit` | 1–500 | default 100 |

`200` → list of payments, newest first · `401`

### `GET /api/payments/{payment_id}` — User

`200` → payment · `401` · `404`

## Administration

### `GET /api/admin/machines` — Admin

Every machine, including deactivated ones. `200` → list of machines · `401` · `403`

### `GET /api/admin/summary` — Admin

`200`
```json
{
  "machines": {"total": 4, "active": 3, "available": 1, "out_of_service": 1},
  "reservations_by_status": {"CONFIRMED": 2, "CANCELLED": 1},
  "payments": {"succeeded": 2, "failed": 1, "refunded": 1, "revenue": 8.0}
}
```
`revenue` is the total of `SUCCEEDED` payments (refunded payments are excluded). `401` · `403`
